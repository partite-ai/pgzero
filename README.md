# pgzero

PostgreSQL 18, embedded in a Go program: a real Postgres server compiled to
WebAssembly and run with [wazero](https://github.com/tetratelabs/wazero).
Each Postgres process (postmaster, backends, background workers, parallel
workers) runs as its own wasm instance inside your process, with shared
memory, signals and sockets provided by a small Go "kernel". There is
nothing to install and no external server to manage.

Typical uses: tests that need a real Postgres without Docker or a local
install, and standalone tools that want a database built in.

## Usage

```go
import (
	"github.com/jackc/pgx/v5"
	"github.com/partite-ai/pgzero"
	"github.com/partite-ai/pgzero/pgzerox"
)

srv, err := pgzero.Start(ctx, pgzero.Config{}) // in memory
if err != nil { ... }
defer srv.Close()

conn, err := pgx.ConnectConfig(ctx, pgzerox.ConnConfig(srv, "postgres"))
```

`pgzerox.PoolConfig` does the same for `pgxpool`, and
`stdlib.OpenDB(*pgzerox.ConnConfig(srv, "postgres"))` gives a `database/sql`
handle. Connections are in-memory pipes (`Server.Dial`), cancel requests
included; no port is opened.

`pgzero.Config`:

- `DataDir`: keep the cluster in a host directory (created and initialized if
  empty) instead of in memory.
- `Settings`: server parameters, as in postgresql.conf.
- `TCP` (and `Port`): also listen on localhost, for `psql` or other tools;
  see `Server.TCPAddr`.
- `Logs`: where the server log goes.

A server starts in well under a second (the first in a process takes a few
seconds longer, to load the compiled engine), and servers are independent,
so tests can each start their own.

### Extensions

- **Bundled with Postgres:** all of contrib that needs no external libraries,
  plus plpgsql. Enable them with `CREATE EXTENSION`. `pg_stat_statements` also
  needs `Settings: {"shared_preload_libraries": "pg_stat_statements"}`, as
  usual.
- **pgvector** 0.8.6 (`CREATE EXTENSION vector`), with HNSW and IVFFlat
  indexes.
- **pgcrypto_lite:** pgcrypto needs OpenSSL, which this build doesn't
  include. `CREATE EXTENSION pgcrypto_lite` gives pgcrypto's
  `gen_random_bytes()` and `gen_random_uuid()`, which need only a strong
  random source (the host's).
- **Not available:** extensions needing external libraries (pgcrypto, uuid-ossp, xml2,
  PostGIS, ...) and the plperl/plpython/pltcl languages.

### go.mod

pgzero works with released wazero (v1.12.0 or later), but runs about twice
as fast on a fork with a faster compiler (the API is upstream's): queries
take a half to a third of the time, and loading data up to six times less.
`replace` directives only apply in the main module, so to use the fork, add
this to yours:

```
replace github.com/tetratelabs/wazero => github.com/mpoindexter/wazero v0.0.0-20260824195113-bbffa6a24693
```

Supported hosts: macOS and Linux (shared memory uses `mmap`).

## Repository layout

The library:

- `pgzero.go`, `pgzerox/`: the API.
- `internal/kernel`: the process host. It runs each Postgres process as a
  component instance, and implements the host interface they import
  (processes, signals, pipes and sockets, shared memory, semaphores).
- `internal/memfs`, `internal/osfs`: the in-memory and host-directory
  filesystems processes see.
- `internal/vmem`: mmap-backed linear memories, so that shared memory is
  mapped at the same address in every process.
- `internal/assets`: the Postgres build the library runs. It is generated by
  `make assets` and committed.
- `internal/gen`, `internal/abi`: generated host bindings and guest ABI
  constants (`make gen`).

How the wasm Postgres is built, in `wasm/`:

- `wit/pgzero.wit`: the host interface, between Postgres processes and the
  kernel.
- `libpgzero/`: the guest side of that interface. It implements the POSIX
  functions Postgres needs and wasi-libc lacks (signals, `fork`+`exec` as
  spawn, sockets, `poll`, shared memory, `dlopen` of statically linked
  modules, ...). `include/` wraps libc headers accordingly.
- `patches/`: the changes to Postgres itself: the wasi port (shared memory
  and semaphores), and a few fixes.
- `extensions/`: extensions of our own (pgcrypto_lite). pgvector is
  fetched into `pgvector/` and built the same way.
- `toolchain/`: the meson cross file and a clang wrapper for the wasi-sdk.
- `scripts/`: linking Postgres with its loadable modules, installation, and
  running the regression suite.
- `cmd/`: build tools. `pgzero-run` runs the development build with host
  directories mounted.

## Building Postgres

Only needed to change the embedded build. You need `go`, `meson`, `ninja`,
`python3`, and bison/flex/perl; `make tools` fetches the rest.

```sh
make tools     # fetch the wasi-sdk and wasm-tools into .tools/
make assets    # clone and patch Postgres, build it, regenerate internal/assets
make test      # the library's tests
make regress   # Postgres's main regression suite, against the wasm build
make regress-pgvector
make bench     # pgbench: pgzero against native Postgres, same version and settings
make bench-go  # the library's own benchmarks (in memory, through pgx)
```

The **Rebuild wasm assets** GitHub Actions workflow does the same on demand
(run it from the Actions tab) and opens a pull request with the new
`internal/assets`.

The Postgres source is checked out into `postgres/` with
`wasm/patches/postgres-REL_18_6.patch` applied. After changing it, run
`make pg-patch` to update the patch.
